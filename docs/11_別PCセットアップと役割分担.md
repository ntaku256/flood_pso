> 2026-08-05 作成。issue#3 の作業中に整理。

## 0. 要点

| | サブPC | メインPC |
|---|---|---|
| 用途 | **機能実装・デバッグ** | **本番生成・重い検証** |
| 生成範囲 | 南部4図郭の crop（数十秒〜） | 御坊全域18図郭 `world-full`（**5.29時間** / 出力2.2GB） |
| 必要データ | 南部4図郭の npz（574MB） | 全18図郭 + FGD一式 |

**原則**: コードの変更と単体検証はサブPCで完結させ、時間と容量を食う本番生成だけメインPCへ持っていく。

## 1. Python 環境

### uv を使うこと（`python3 -m venv` は失敗する）

このマシンには `python3-venv`（`ensurepip`）が入っておらず sudo も使えないため、標準の venv 作成は失敗する:

```
The virtual environment was not created successfully because ensurepip is not
available.  On Debian/Ubuntu systems, you need to install the python3-venv package
```

そのため **uv を既定の手順とする**:

```bash
cd flood_pso
uv venv .venv --python 3.10
uv pip install --python .venv/bin/python -r requirements.txt
```

**既存の `.venv` には pip が入っていない**。`.venv/bin/pip` は存在しないので、パッケージ追加も uv 経由で行うこと:

```bash
uv pip install --python .venv/bin/python <package>
```

実行は `.venv/bin/python` を直接叩く（`Makefile` の `PY` 変数もそうなっている）。

### 検証済みの組み合わせ

Python 3.10.12 + `requirements.txt` のピン留めバージョン。
2026-08-05 に uv でクリーン環境を作り、全12パッケージの import 通過を実測確認済み。

> `opencv-python` は `requirements.txt` に載っていたが `cv2` は `src/` 内で一度も import されていないため削除した。
> 逆に**実際に使っている `rasterio` と `shapely` が抜けていた**ので追加した。

## 2. 必要な外部データ

コードだけでは生成できない。以下は別途配置が要る。

### 2.1 LiDAR 点群（和歌山県 3次元点群オープンデータ）

**生 txt は転送しないこと。npz キャッシュだけでよい。**

| 形式 | サイズ | 備考 |
|---|---|---|
| 生 txt | **1図郭あたり約860MB**（grd 134MB + org 724MB） | 18図郭で約15GB |
| npz キャッシュ | 南部4図郭で **574MB** | 実際の生成はこちらを読む |

`data_cache/wakayama_lidar/` に配置する。命名規則:

- `{図郭コード}_grd.grid{解像度}m_pp.npz` — 地表DEM（ground、地物除去済）
- `{図郭コード}_org.grid{解像度}m_{exc3|keep3}.npz` — DSM（建物実高さ。`exc3`=樹木クラス除外 / `keep3`=保持）
- `{図郭A}_grd+{図郭B}_grd+...grid{解像度}m_pp.npz` — 複数図郭の結合 mosaic

解像度は `--scale` に対応（`scale 1.5` → `0.666667m`、`scale 2.0` → `0.5m`）。

**現在サブPCにあるのは南部4図郭のみ**: `06RC904` / `06RC913` / `06SC002` / `06SC011`
結合 mosaic の範囲: lat 33.820086〜33.847364 / lon 135.157140〜135.200608（約3×4km、dem shape (4556, 6030)）

**欠落している**: `06RC701` `06RC702` `06RC703` `06RC704` `06RC711` `06RC713` `06RC801` `06RC802` `06RC803` `06RC804` `06RC811` `06RC813` `06RC902` `06RC911` の14図郭、および18図郭結合 mosaic（427MB）。
→ **メインPC側にあるはず。無ければ和歌山県オープンデータから再取得が要る。**

出典表記は必須: 「和歌山県 3次元点群データ（航空レーザ測量）を加工して作成」

### 2.2 基盤地図情報 FG-GML（国土地理院）

`../kennkyuu20260114/地形データ/` 配下（Makefile:21-22 が相対パスで直参照している）。

| ディレクトリ | サイズ | 内容 |
|---|---|---|
| `FG-GML-503561-ALL-20251001/` | 79MB | 北側メッシュ。BldA(建物28MB) / RdEdg(道路12MB) / WA・WStrA(水域) / RailCL(鉄道224KB) |
| `FG-GML-503551-ALL-20260101/` | 19MB | 南側メッシュ。同上（BldA 6.4MB） |

御坊全域は lat 33.8333 を跨ぐので**両メッシュの union が要る**。
`kennkyuu20260114` は git-LFS 管理なので、clone 後に `git lfs pull` が必要。

### 2.3 OSM フィーチャ（Overpass）

`data_cache/osm/` 配下。**Makefile が要求するが現在存在しないもの**:

- `gobo_bridges_full_geom.json`（全御坊144本 full_geom）
- `gobo_tunnels_geom.json`
- `gobo_power_geom.json`（送電線+鉄塔）
- `gobo_parking_geom.json`（駐車場）

現在あるのは図郭別の `gobo_bridges_{002,011,703,704,801,804,902,904,913}_geom.json` と `gobo_bridges_geom.json`（全御坊、23KB）。

> **注意**: これらが無いまま `world-full` を回すと、以前は**無言で橋0本のワールドが出来ていた**。
> issue#3 で「明示指定されたパスが存在しない場合はエラーで停止」するよう修正した。

Overpass から取り直す場合は tizucraft の `Makefile` の `osm` ターゲットが参考になる（bbox とクエリが書いてある）。

### 2.4 オルソ画像（地理院）

`data_cache/gsi_ortho/` に生成時にオンデマンドでダウンロードされる。事前配置は不要。
既定レイヤは `ort`（整備済オルソ）。緑が出ない場合のフォールバックが `seamlessphoto`。

## 3. 転送するもの / しないもの

### 転送する

- リポジトリ本体（コード）
- `data_cache/wakayama_lidar/*.npz`（**txt は不要**）
- `data_cache/osm/*.json`
- `../kennkyuu20260114/地形データ/FG-GML-*`

### 転送しない（再生成可能）

- `results/anvil/`（11GB）— Anvil ワールド出力
- `results/nbt/`（9.3GB）— 中間 structure NBT
- `results/world/` `results/inspect/` `results/data_preview/gobo_full/`
- `data_cache/wakayama_lidar/*.txt`（3.9GB）— npz があれば不要
- `.venv/`（uv で作り直す）

> リポジトリには `.gitignore` に該当するのに tracked のままのファイルが **46件・107MB** ある
> （`results/nbt/hd/*.nbt` `*.litematic` が36件）。clone を軽くするなら `git rm --cached` で追跡から外す余地がある。
> ただし履歴には残るので、`git clone --depth 1` を使うのが手っ取り早い。

## 4. 生成コマンドの使い分け

```bash
# サブPC: 高速反復（数十秒）。橋・トンネルのコード修正 → 確認 のループ用
make crop                      # 既定: 中心 lat 33.8337 / lon 135.1789, 400m角
make crop CLAT=.. CLON=.. W=.. # 中心・サイズ上書き

# サブPC: 南部4図郭でのオプション検証（十数分）
make world-test

# メインPC: 御坊全域18図郭の本番生成（5.29時間 / 2.2GB）
make world-full
make world-full LEGEND=--legend-layer   # 地下にLayer C可視化層を入れる場合
```

> `make world-test` は元々 `06RC701/702` を参照していて**入力欠落で即死していた**。
> issue#3 で残存する南部4図郭へターゲットを切り替えた。

### gobo_zeniki_v3 について

プレイに使っていた `gobo_zeniki_v3` は Makefile に存在しない。実体は
`make world-full LEGEND=--legend-layer` を **commit 138b4ee** で回した出力（`results/anvil/gobo_zeniki_v2`）を
Windows の `saves/` へ手コピーして改名したもの（中間NBTの `flood_pso_meta` に `git_revision` が刻印されていて確定）。

**橋バグ修正 bb20921 より前のビルド**なので、基準にするなら現行の `results/anvil/gobo_zeniki_v2`（bridgefix版）の方が新しい。

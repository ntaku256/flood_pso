# 07. 地形レンダ改善（Tellus 風 enhanced モード）

> 起点: 2026-05-12
> 動機: viewer で見たとき「海岸線・海の表現が雑」「緑斜面でも階段が目立つ」「地表ブロックが不自然」の 3 点を改善する
> 参考: `web-app/Tellus/` (Earth-scale Minecraft Fabric mod) の worldgen 実装

## 1. 何が変わったか

`flood_pso/src/nbt_export.py:export_to_nbt` に **terrain_quality** 引数を追加：

| 値 | 挙動 | 用途 |
|---|---|---|
| `enhanced`（**新規 default**） | 新ファイル `terrain_render.py:dem_to_blocks_enhanced` を使用 | Tellus 風の改善ブロック化 |
| `legacy` | 従来 `nbt_export.py:dem_to_blocks` をそのまま使用 | 旧出力との比較・回帰用 |

`make_nbt_hd.py --quality {enhanced,legacy}` / `make_nbt.py --quality {...}` で切替可能。
`legacy` は出力ファイル名に `_legacy` サフィックスが付き、enhanced 出力（無印）と並存。

## 2. Tellus からの移植マッピング

| Tellus 実装 | flood_pso での対応 | 備考 |
|---|---|---|
| `worldgen/MountainSurfaceRules.classifyApproximateSurface` | `terrain_render.classify_surface_block` | 標高 + slope + convexity で stone/gravel/grass を決定。土地被覆 (ESA WorldCover) は使わず DEM 由来量だけで判定する簡易版 |
| `worldgen/MountainSurfaceRules.classifyShorelineMaterial` | 海岸距離による sand / gravel 上書き（`classify_surface_block_grid` 内） | shoreline 距離 ≤ 8m → sand、≤ 25m & 標高 < 1.5m → gravel |
| `worldgen/OceanClassification.isOcean` | `terrain_render.make_sea_mask` | NaN または elev ≤ sea_level を海と判定 |
| `worldgen/WaterSurfaceResolver` (海岸距離→水深) | `terrain_render.distance_to_shore` + `make_ocean_depth` | scipy.ndimage.distance_transform_edt で海岸からの距離を計算 → 200m 沖で max_depth m に到達する線形 |
| README §Settings "Limit Shoreline Blend on Cliffs" | `terrain_render.cliff_aware_smooth` | gaussian smoothing するが、slope ≥ cliff_threshold_m_per_m の崖は元値を保持 |
| README §Settings "Terrestrial / Oceanic Height Scale" | `dem_to_blocks_enhanced(v_exag_land, v_exag_sea)` の二段化 | デフォルトでは `v_exag_sea = v_exag_land * 0.33`（自動） |
| `worldgen/TerrainAnomalyRepair.repairHeightFromNeighbors` | **未移植**（御坊 DEM の継ぎ目異常はユーザ言及なし） | 必要なら 137 行の純関数を numpy 化可能 |

## 3. 改善 5 点（enhanced モード）

1. **Cliff-aware smoothing**（緑斜面の階段化抑制）
   - DEM に gaussian sigma=1.0 (cells) を適用、ただし slope ≥ 0.4 m/m (~22°) の崖セルは元値を維持
   - 効果：緩斜面の階段差が滑らかに、崖は保たれる
2. **海岸線・海の表現**
   - 海セル（NaN または elev ≤ sea_level）を距離変換で海岸からの距離 [m] に変換
   - 沿岸 0m → 沖合 200m で max_depth_m (既定 8m) まで線形に水深増加
   - 海底に sand（浅）または gravel（深）を敷く + 直下 3 ブロックに stone 地盤
   - 水柱を sea_level + 1 まで積む
3. **地表ブロック判定の改善**
   - DEM 由来 4 量で判定（標高、slope、convexity、海岸距離）
   - 海岸 ≤ 8m → sand
   - 海岸 ≤ 25m & 低標高 → gravel
   - slope ≥ 1.0 (45°) → stone (rocky scree)
   - slope ≥ 0.7 (35°) & 凸性 ≥ 0 → gravel (talus)
   - 標高 ≥ 200m または (≥ 120m & slope ≥ 0.4) → stone
   - それ以外 → grass
4. **陸/海で v_exag を分離**
   - `v_exag_land`（既定 = 引数 `v_exag`）と `v_exag_sea = v_exag_land * 0.33`（既定）
   - 陸は誇張で見栄えを保ちつつ、海は実深度に近づける
5. **地盤柱の深化**
   - 従来 3 → 既定 8 ブロック
   - 視点角度で底が抜けにくく、greedy mesh の cull で内部はほぼ描画されないので性能影響は限定的

## 4. 新パラメータ（NBT meta に記録）

`export_to_nbt(terrain_quality="enhanced", ...)` で生成された NBT は `flood_pso_meta` に追加で：

```
terrain_quality          : "enhanced"
sea_level_m              : 0.0
ocean_max_depth_m        : 8.0
smooth_sigma_cells       : 1.0
cliff_threshold_m_per_m  : 0.4
v_exag_sea               : 0.99   (= v_exag_land * 0.33)
deep_ground              : 8
```

viewer 側で特別な対応は不要（`ui.rs` の "raw flood_pso_meta" collapsing 内に自動表示）。

## 7. Phase 7: Tellus データソース直接取得 + Mapzen 上書き（2026-05-12 追加）

### 7.1 経緯

Phase 6 の `enhanced` モードでは `_legacy` と比べて統計差は出たが、viewer で見ると依然として **緑/灰の柱が密集する「針葉樹林のような」見た目** が残った（スクショ確認）。原因は:

1. **`v_exag=3` が大きすぎ**：1m 標高差が 3 ブロックの段差になり、ダウンサンプル後の隣接セル分散がそのまま立体ピン化
2. **GSI 5m DEM の隣接セル分散**：5m 格子の元データが NBT 化時に 10m/block にダウンサンプルされる過程で平均化されない高周波成分が残る
3. **deep_ground=8 は地下に stone を増やしただけ** で、greedy mesher 上は内部 cull で見た目には寄与しない

### 7.2 Phase 7 の対応

新ファイル `src/tellus_data.py` を追加し、Tellus mod が内部で使うのと **同じデータソース** を Python から直接取得：

| データ | 出所 | API |
|---|---|---|
| Mapzen Joerd Terrain Tiles | AWS Open Data Registry (`elevation-tiles-prod.s3.amazonaws.com/terrarium/{z}/{x}/{y}.png`) | `tellus_data.fetch_mapzen_dem(bbox, zoom)` |
| ESA WorldCover 2021 v200 | AWS S3 (`esa-worldcover.s3.amazonaws.com/v200/2021/map/...`) | `tellus_data.fetch_esa_worldcover(bbox)`（rasterio 必須） |

**Tellus mod 本体（Minecraft Fabric mod）は起動しない**。データソースだけ共有することで「Tellus と同じ品質、Minecraft 不要、オフラインキャッシュ可」を実現。

### 7.3 構造変更

- `tellus_data.fetch_mapzen_dem(...)` — terrarium PNG (R*256+G+B/256-32768) をデコード、モザイク化
- `tellus_data.reproject_to_grid(src, src_meta, dst_meta)` — 経緯度ベースの bilinear 再投影（`scipy.ndimage.map_coordinates`）
- `tellus_data.fetch_esa_worldcover(...)` — N33E135 タイル取得 + crop（rasterio）
- `tellus_data.cover_class_to_block(cover, ...)` — ESA 11 クラス → flood_pso パレット
- `nbt_export.export_to_nbt(..., terrain_source="gsi"|"mapzen", mapzen_zoom=15, use_esa=False)` — `terrain_source="mapzen"` のとき Mapzen DEM を取得し、inundation を Mapzen grid に bilinear 再投影
- `terrain_render.classify_surface_block_grid_esa(...)` — ESA cover を主軸に、急斜面・高標高で stone 上書き
- `terrain_render.dem_to_blocks_enhanced(..., cover_patch=None)` — ESA cover が渡されれば優先

### 7.4 新 CLI フラグ（`make_nbt_hd.py`）

```bash
--terrain-source {gsi,mapzen}    # 表示用 DEM ソース。校正は常に GSI
--mapzen-zoom 15                 # 14≈9.5m, 15≈4.8m, 16≈2.4m
--use-esa                        # ESA WorldCover で土地被覆別ブロック割当
--v-exag 1.5                     # プリセット v_exag を上書き（針葉樹感対策）
--smooth-sigma 2.0               # cliff-aware smoothing の sigma [cells]
--cliff-threshold 0.4            # 急斜面 slope 閾値 [m/m]
```

## 8. Phase 8: 建物の内部化・樹木の壁優先・地下データ層（2026-06-24）

歩行ワールドの「中に入れる建物」と「解釈の可視化」。すべて `terrain_render.dem_to_blocks_enhanced`＋`block_palette` ＋`make_nbt_hd` フラグ。地表色（写真モザイク）には触れていない。

### 8.1 建物の内部化（既定 ON、`--solid-buildings` で旧ソリッドに戻せる）
- **空洞化**：footprint の外周セルだけ壁、内側は空気（`building_id` の4近傍差分で周壁/角を判定）。
- **ガラス窓**（`glass`）：壁が走る向きに沿って**3マスおき＝窓間に最低2マスの壁**（`_is_window`）。スタイル別＝家=各階に窓 / ビル(`building_style_for_type`)=全階連窓 / 工場(無壁舎)=高所ハイサイド窓。角は柱(窓なし)。
- **階ごとの床**＋**内部照明 `sea_lantern`**（疎な内側格子の天井灯、glowstone から変更）＋**出入口**（内側を持つ棟に1枚、道路側の周壁に2マス開口）。
- **筒抜け修正**：屋根の段差で壁が抜ける問題を 2 段で解消 — ①寄棟は**軒高(周壁の最小高さ)より上を中実の屋根**に、②**棟ごとに平らな基準面(最高地盤)に載せ基礎で段差を充填**（傾斜地対策）。これで出入口・窓以外は完全に閉じる。

### 8.2 樹木の壁優先（`_putt`）
- 樹木は **建物＋軒(8近傍1マス外周)** には葉も幹も置かない（`no_tree`＋`_putt` を `binary_dilation(building,3x3)` で）。litematic は後勝ちなので、これが無いと後置きの葉が壁を上書きして透ける。検証: 壁にめり込む葉が 147→ほぼ0（残りは灰色地表のオルソ色を壁と誤検出した偽陽性）。

### 8.3 地下データ層（`--legend-layer`、既定 OFF）
土地利用の解釈を色付きガラスで地下に表面化（光源なし、コマンドで読み取り・応用向け）。**重なる洪水・樹木は層を分けて別の高さ**に置き、間隔をあける:
- **y=0 土地利用ベース**（全敷き）: 建物=赤/道路=黒/海=青/河川=水色/橋=橙/地表=白。
- **y=2 洪水**（全敷き二値）: 浸水=水色 / 非浸水=白。
- **y=4 樹木**（全敷き二値）: 木=緑 / それ以外=白。
- 凡例有効時は**世界全体を `_lift=6` 持ち上げ**、地形/構造の最低 y を 6 に制限（基礎は `max(_lift, …)`）。底に凡例3層(間に空気1段)が並び、地形と入れ替わらない。検証図 `results/nbt_preview/gobo_legend_3layers.png`。
- 用途: 地下を見れば各セルの解釈が分かり、`/execute if block ~ ~ ~ minecraft:light_blue_stained_glass`(y=2) で浸水判定 等。

### 8.4 パレット追加（`block_palette`、いずれも `_NON_MATCH` でオルソ色マッチ対象外）
`glass`（窓）・`glowstone`・`sea_lantern`（内部照明）・`{white,red,orange,light_blue,blue,green,black}_stained_glass`（凡例）。viewer 用 `block_colors.rs` も `python src/block_palette.py export-viewer` で更新（別repo `flood_pso_viewer`）。

### 8.5 既知の注意
- 凡例層は +約169万ブロック（3層×全セル）。容量増。`--legend-layer` はオプトイン。
- 「畑」の専用分類は無し（地表=白に含む）。農地筆は別途差し戻し済み（[[project_gobo_precision]]）。
- 生成中心が LiDAR タイル外だと DEM 空→ZeroDivisionError（未ガード）。

### 8.6 土台層（砂/砂利の落下防止, 2026-06-24）
海底の砂/砂利は支えが無く**ブロック更新で落ちていた**。対策2点:
- **全セルの最下 y=`_lift-1` に deepslate の土台層**を敷く。そのため世界を `_lift` 持ち上げ（凡例OFFでも `_lift=1` で y=0 が土台、地形は y≥1）。deepslate は割れるので、下にある凡例層は掘って到達できる。
- **屋根/軒の `red_sand` も非重力 `orange_terracotta` へ置換**（既存の sand→sandstone / gravel→andesite 置換に追加。dict 化）。
- 検証: 落下する重力ブロック(sand/gravel/red_sand で直下が空気)の数 = **0**（凡例あり/なし両方）。
